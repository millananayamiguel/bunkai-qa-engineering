# BK-601 — Business Rules

> Jira field: `customfield_10152` · [View in Jira](https://jira.upexgalaxy.com/browse/BK-601)

- ***A restore is the exact inverse of one archive — not of every archive that ever touched the subtree.*** Restoring a Module brings back precisely the rows that Module's own archive took down. Anything already archived before that archive ran stays archived. A restore that over-restores destroys a decision somebody made deliberately, and is a defect, not a convenience.
- ***Exactness must be recorded, not inferred.*** The system must be able to state which rows one archive took down, rather than deduce it from a shared timestamp. Inference happens to work today only because a cascade archives one subtree per action; it stops working the moment more than one subtree is archived together, which is already named as future work.
- ***The tree may never hold an active Module under an archived one.*** Restoring a Module whose parent Module is still archived is refused and names the archived ancestor. An active row nobody can reach in the tree is invisible-but-live: it still counts, it is still offered for reuse, and nobody can see it. Silently re-parenting it, or silently restoring its ancestors, are both worse — each edits structure the user never asked about.
- ***A restore either completes whole or does nothing.*** The archive is one atomic act across four kinds of record; its inverse must be too. A half-restored subtree is a corrupt tree, not a partial success.
- ***A restore may be refused by the rules the Project enforces on any active Module.*** Nesting depth and sibling-name uniqueness are invariants of the live tree, not of the archive. If restoring would break one, the restore is refused and says which rule blocked it. It is never allowed through, never truncated, and never silently renamed.
- ***Hiding archived rows is the default; showing them is always explicit.*** No listing ever mixes archived rows into an unfiltered view. The opt-in is per view and does not persist as a hidden setting somebody forgets they turned on.
- ***An archived row is always visibly archived.*** Opting in shows it with its archived state on its face. A row that reads as active but is archived is worse than one that is hidden.
- ***The opt-in changes visibility, never permission.*** Anyone who can read a Project can see what is archived in it and when. Opting in never surfaces a row the same person could not otherwise see.
- ***Restoring requires the access that already permits archiving.*** Reading the archive needs read access; undoing it needs write access. A member who cannot archive is offered no restore.
- ***Archive and restore are both idempotent and both reversible.*** Restoring an active Module is reported as success and changes nothing, and writes no audit entry — an event log records events, and a no-op is not one. Neither action ever destroys a record.
- ***Every restore is auditable, separately from the archive it undoes.*** One workspace Activity Stream entry per restore, naming the Module and the actor, and recording how many rows of each kind came back. The archive entry is never rewritten or removed by the restore; the pair is the history of the decision.
- ***The archive filter is selective, never uniform.*** Surfaces that offer something for use may hide archived rows. Surfaces that report what already happened — traceability, coverage, past execution evidence — must keep resolving them. This Story adds no filter to a reporting surface, and inherits the rule already ratified for ATCs and Tests rather than restating a second version of it.
- ***This Story reuses the archive vocabulary rather than authoring a second one.*** The archived-row treatment, the restore action and the reversible-confirmation copy are the same words, in the same shapes, that [https://jira.upexgalaxy.com/browse/BK-571#icft=BK-571](https://jira.upexgalaxy.com/browse/BK-571#icft=BK-571) specifies for ATCs and [https://jira.upexgalaxy.com/browse/BK-596#icft=BK-596](https://jira.upexgalaxy.com/browse/BK-596#icft=BK-596) reuses for Tests. Only the host surface differs, because Modules live in the explorer tree.
